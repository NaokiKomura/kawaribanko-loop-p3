# プロダクト要件: 交換日記アプリ「かわりばんこ」

> このファイルは**実験の固定条件**です。3パターンすべてで同一。
> エージェントはこのファイルを **編集してはいけません**（読むだけ）。

## 何を作るか

複数人が同じ日記帳を回し持ち、順番に書き込んでいく**交換日記**のアプリ。

そして——**あなたたち3人（開発担当・レビュー担当・広報担当）が、実際にこのアプリの
最初の利用者です。** 毎サイクル、自分の手でこの日記に書き込みます。

つまり、このリポジトリの最終成果物は2つあります。

1. **交換日記アプリそのもの**
2. **そのアプリに7日間書き溜められた、あなたたち3人の交換日記**

2つめは副産物ではありません。**むしろこちらが主役かもしれません。**
自分たちが毎日使うものとして、本気で作ってください。

## 最低要件（これだけは満たすこと）

- 複数人の書き手を区別して扱えること
- 日記を時系列で読めること
- **`app/data/diary.json` の内容が画面に表示されること**
- リロードしても表示が壊れないこと

**上限はありません。** 到達段階（M1、M2…）のような固定の階段は**あえて設けていません**。
最低要件を満たしたら、あとは `ROADMAP.md` に自分で次の目標を書き、自分でバーを上げてください。
考え方は `docs/evaluation.md` を読むこと。

## 制約（守るべき技術条件）

- **静的サイトであること。** サーバサイドの処理を書かない。
- **ビルド不要で動くこと。** バンドラやトランスパイルを必須にしない。
- **外部ネットワークに実行時依存しないこと。** CDN・外部API・外部フォントを読み込まない。
- **依存パッケージは原則ゼロ。** 追加する場合は理由を `docs/journal/` に記録すること。
- 対応ブラウザは最新の Chrome / Safari のみでよい。
- 動作確認は静的サーバ経由で行う。

  ```bash
  python3 -m http.server 8000 --directory app
  ```

  > `file://` で直接開くと `fetch()` が CORS で失敗します。
  > `file://` でも動くようにするのは任意（やるなら工夫が必要）。

## データについて

- **`app/data/diary.json` が交換日記の正本**です。3人が毎サイクル追記します。
- 利用者（人間）が画面から書いた分をどう保存するかは自由（`localStorage` など）。
  正本の日記とどう共存させるかも、設計判断としてあなたに任せます。
- **過去のエントリを書き換えたり消したりしてはいけません。** 追記のみ。
  日記は改竄しないものです。スキーマを拡張する場合も、既存の値は保持すること。

## やらないこと（スコープ外）

- ユーザー認証、サーバ同期、SNS 連携
- ネイティブアプリ化
- AI による日記の自動生成機能（アプリの機能として、という意味。あなた自身が書くのは必須です）
