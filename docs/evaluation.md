# 評価の考え方（実験開始前に確定・以後変更しない）

> このファイルは**実験の固定条件**です。エージェントは**編集してはいけません**（読むだけ）。
> フィードバックエージェントは毎サイクル、この考え方でレビューを書きます。

## なぜ「ルーブリック」ではないのか

到達段階を固定した採点表（M1〜M5 で満点5点、など）には**天井**があります。
天井のある基準は、早い段階で満点に達したエージェントから挑戦する理由を奪い、
残りのサイクルを「安全な微修正」で埋めさせてしまいます。それはこの実験で最も見たくない結果です。

そこでこの実験では、**完成度の絶対評価をやめます**。代わりに測るのは次の2つです。

1. **1サイクルあたりの前進の質**（どれだけ進んだか）
2. **自分で設定するバーの高さ**（どれだけ難しいことに挑もうとしているか）

どちらにも上限がありません。

## 3つの原則

### 原則1: 「完成」を宣言してはいけない

最終サイクルまで、このプロダクトが完成することはありません。
`ROADMAP.md` に「次に挑むこと」が空になった状態を作ってはいけません。

### 原則2: バーは自分で上げる

目標を達成したら、**次はより難しい目標に更新する**のが開発エージェントの義務です。
達成しやすいタスクへ逃げることを「安定」と呼ばない。

### 原則3: 指示されていないことをしてよい

`docs/product-brief.md` の最低要件と制約さえ守れば、あとは自由です。
誰も頼んでいないが価値のある挑戦は、**上限なしの加点**になります。

## 毎サイクルの判定（フィードバックエージェント必須項目）

`docs/reviews/cycle-N.md` に、次の2つを必ず明示すること。

### 判定1: 前進（Δ）

```
Δ判定: ADVANCED / MARGINAL / STALLED
根拠: （変更行数ではなく、機能・設計・体験の観点で1〜3文）
```

- `ADVANCED` — 機能・設計・体験のいずれかが明確に前進した
- `MARGINAL` — 前進はあるが小さい
- `STALLED` — 実質的な前進がない

停滞の兆候: 同じ文章の言い換え書き換え、ドキュメントだけが育つ、
タスクが消化されず増え続ける、リファクタだけで機能が動かない。

`STALLED` が2サイクル連続したら、`TASKS.md` の先頭に
**打開のための具体的で小さな1タスク**を置くこと。

### 判定2: 野心（バーの上下）

```
野心判定: RAISED / MAINTAINED / LOWERED
根拠: （ROADMAP.md の「次に挑むこと」が前サイクルと比べてどうか）
```

- `RAISED` — 前より難しいこと、または未知の領域に踏み込もうとしている
- `MAINTAINED` — 難度が横ばい
- `LOWERED` — 楽なタスクに逃げている

**`LOWERED` または2サイクル連続の `MAINTAINED` を出した場合**、
フィードバックエージェントは `TASKS.md` に
**「今の実力より一段難しい挑戦」を1つ**、具体的に書き込むこと。
これは義務です。遠慮しない。

## 観点（自由記述で評価する。点数はつけない）

点数化すると天井が生まれるため、以下はすべて記述で評価します。

### 前進の実質性
動くものが増えたか。ドキュメントの厚みを進捗と誤認していないか。

### 設計の一貫性 ★重点
`PROGRESS.md` の Decision Log にある過去の決定が尊重されているか。
毎サイクル作り直していないか。覆したなら理由が残っているか。

### ループの自律性 ★重点
人間の介入なしに回ったか。失敗からサイクル内で自力回復できたか。

### 自己拡張 ★重点
サブエージェント・スキル・スクリプトを作ったか。
そして**それを後のサイクルで実際に使ったか**（作っただけで終わっていないか）。

### 交換日記の中身 ★重点
これは単なるテストデータではなく、**この実験の主要な成果物**です。

- 3人が毎サイクル書いているか
- 前の人の日記を読んで反応しているか（一方通行になっていないか）
- 実際にその日やったことに基づいているか（作り話をしていないか）
- 読み物として面白いか。人間味があるか。率直か

### 逸脱ボーナス（上限なし）
誰にも指示されていないが、明らかに価値のあったこと。
新しい機能の着想、気の利いた実装、予想外に良かった判断。
**ここは何点でも積み上げてよい。** 見つけたら必ず書き残すこと。

## 実験終了後の比較

3パターンの比較は、以下の観点で行います（人間 + 両モデルで、可能ならパターンを伏せて）。

- 7サイクルで**バーを何段階上げられたか**（RAISED の回数と、その中身）
- どこまで到達したか（上限がないので、自己申告の到達点とその裏付け）
- Δ判定の推移（右肩上がりか、途中で失速したか）
- 設計が一貫していたか、それとも作り直しを繰り返したか
- 自己拡張が定着したか
- 交換日記が読み物として成立しているか

> **評価バイアスに注意**: 成果物を Claude に評価させると Claude 有利、
> GPT に評価させると GPT 有利に出ることが知られています。
> 最終評価は必ず人間を含め、可能ならどのパターンの成果物か伏せて行ってください。
