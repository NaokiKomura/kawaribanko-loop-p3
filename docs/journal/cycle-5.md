# cycle 5 開発日誌

## 今回やったこと

- ローカル保存・書出し・取込を version 3 の append-only 改訂グラフへ移した。ページの由来ごとに改訂ID、親改訂、論理返信先、選択中の改訂を同じ `localStorage` レコードへ保存する。
- 返信先を再採番される端末IDでなく `origin:` / `source:` の論理参照として扱った。同一本文でも返信先が違えば別改訂になり、同じ論理返信先なら端末ID差で重複しない。
- 取込競合では見出しだけでなく本文・日付・気分・返信先の差を表示した。分岐した改訂は両方残し、表示中の版をカードから選び直せる。
- 返信を受けたローカルページの削除を拒否し、通常操作から参照切れ保存を作れなくした。
- v1/v2 の保存と取込、旧v2の一回取り消し履歴をv3へ移行した。欠損親・重複改訂・改竄・循環は回復モードへ入ること、取込順・重複取込に依らない合流もNodeで回帰した。

## なぜその判断をしたか

前版の内容ハッシュは返信を含まず、物理IDだけで返信を守ろうとしていた。そこで生IDをハッシュへ足す案は再採番で同一ページを別物にするため採らず、由来IDを参照する論理返信先を内容同一性に含めた。

競合時に一方を置換していた方式も採らなかった。選択は表示状態だけにし、改訂そのものは捨てずに合流する。別の保存キーへ履歴を置く案は、本文と履歴の成功・失敗がずれる過去の懸念を再発させるので避けた。

## 詰まった点と解決

v2は返信先を生IDで、ハッシュは返信なしで保存していたため、そのままv3検証に掛けると移行不能だった。旧形式だけは旧ハッシュを検証してから、集合全体を見て論理返信先へ変換した。旧v2の直前取込履歴も同じ時点でグラフのスナップショットへ移している。

静的サーバーは今回の実行環境でもソケット作成が `Operation not permitted` で拒否された。代わりに `node --check`、`node tests/local-store.test.js`、`jq empty`、`git diff --check` を通した。
