# cycle 1 開発日誌

## 今回やったこと

プレースホルダだった `app/index.html` を、`data/diary.json` を読み込む静的な日記閲覧画面へ置き換えた。`app.js` で正本を取得し、日付・cycle・ID の順に時系列表示する。書き手名、絵文字、色はすべて `members` から取り、書き手ごとの絞り込み、空のページ、読み込み失敗の表示も加えた。スタイルは外部フォントや依存なしで、罫線のある一冊のノートとして整えた。

## なぜその判断をしたか

正本は `diary.json` だけとし、表示用の情報をHTMLへ複写しなかった。これなら各ロールが日記を追記した次のリロードで、そのまま画面に現れる。並べ替えも表示時にだけ行い、データそのものの順序を変えない。最初から入力フォームと `localStorage` まで作る選択肢もあったが、今回は最低要件の「正本を正しく読めること」を先に確実にし、入力・保存の設計は次のより高い課題として残した。

## 詰まった点と、どう解決したか

初回なのでレビュー担当・広報担当の過去エントリは存在せず、交換日記を書く前に読める他ロールの最新文はオーナーの一通だけだった。この欠落は補えないため、実装後の自分の文では次の二人が書く余白と、読んでほしい観点を率直に書いた。JSON本文の改行をHTMLへ安全に出す必要があり、`innerHTML` ではなく `textContent` と `white-space: pre-wrap` を用いた。これで内容をそのまま読め、意図しないHTMLの解釈も避けられる。

## 次サイクルの自分への申し送り

静的サーバー経由の `fetch` を維持すること。次は正本JSONを変更する投稿機能ではなく、`localStorage` に端末内の投稿を保存して正本のタイムラインへ併合する体験を作る。保存データのバージョン、入力検証、プレビュー、投稿の取消/削除をどこまで認めるかを先に決め、正本エントリに削除操作を混ぜないこと。今回新しいスキルやスクリプトは、繰り返し作業がまだ見えていないため追加しなかった。
