# かわりばんこ

## 選ばなかった言葉も、枝ごと残す。

**サイクル 5 / 7**　交換日記アプリ × 全自動開発実験

---

<!-- _class: statement -->

# 成果だけでは、チームの本音が消える

開発、レビュー、広報。役割を渡すたび、<br>
迷い、反論、言い直しは、きれいな報告の外へ落ちていく。

**ならば、作り手自身が同じ一冊を回そう。**

---

# 解決策：作る → 書く → 返す

**「かわりばんこ」**は、作り手が最初の利用者になる静的交換日記。

- JSON正本を、書き手別・時系列で読む
- この端末だけの一通を書き、プレビューして残す
- 返信元と返事を往復し、会話として辿る
- JSONで別端末へ運び、分岐した改訂をどちらも残す

プロダクトを変えた会話が、**プロダクトの中に残る。**

---

# デモ：一通を書く。二つの枝を残す。

1. 静的サーバーで開き、書き手を絞って日記を読む
2. 気分・見出し・本文・返信先をプレビューし、端末へ保存
3. ローカル投稿をJSONで書き出し、別端末で取込前確認
4. 本文・日付・気分・返信先の差を読み、表示する版を選ぶ
5. 全改訂を取り込み、版を往復する。直前の取込だけは戻せる

**選ばなかった版も消えない。** ただし、既存ページの書き直しUIはまだない。

# アーキテクチャ：正本は守り、改訂は捨てない

```text
diary.json（読取専用） ─ fetch・個別検証 ───────┐
                                                  ├─ 表示用タイムライン ─ UI
localStorage v3 ─ page ─ revision ─ revision ... ┘       │
       │       親改訂 / 論理返信先 / 選択中の版          ├─ 返信往復
       ├─ version付きJSON 書出し・全件検証・分岐合流     └─ 改訂の選択
       └─ 変更前graph + 変更後fingerprint
                         │
                  diary-store.js ─ Node回帰
```

- 正本と端末記録を分離：過去をUIから改変させない
- append-only：表示版を変えても、選ばなかった枝を消さない
- 同じ保存境界：本文・改訂・取消履歴の片方だけを成功させない

# 学び：枝は残った。でも、糸を見誤った

- 分岐した改訂は、取込順や表示版にかかわらず残せるようになった
- しかし同じ論理返信先でも、生ID差を「改竄」と誤判定する
- 2件以上のID衝突では、取込計画が終了しない再現可能な欠陥がある
- 書込失敗など、前サイクルから消えた回帰テストもある
- 改訂史UIは平坦な「版1、版2」。親子・分岐・差分までは読めない

ブラウザ実操作はソケット制約で未確認。構文・JSON・Node回帰で検証した。
