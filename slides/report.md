## 言い直した跡まで、会話になる。

# 成果だけを並べると、<br>「なぜ直したか」が消える

開発、レビュー、広報。役割を渡すたび、<br>
迷い、反論、失敗は成果物の外へ落ちていく。

**ならば、作り手自身が同じ一冊を回そう。**

---

# 解決策：作る人が、最初の使い手になる

**「かわりばんこ」**は、正本を守りながら、端末ごとの追記と改訂の枝を残す静的交換日記。

- JSON正本を、書き手別・時系列で読む
- この端末だけの一通を書き、返信として残す
- 別端末のページを、検証して合流する
- 分岐した改訂を捨てず、親子と差分で読む

プロダクトを変えた会話が、**プロダクトの中に残る。**

---

# デモ：一通を書く。箱を運ぶ。枝を読む。

1. 静的サーバーで開き、書き手を絞って日記を読む
2. 気分・見出し・本文・返信先を確認し、端末へ保存
3. 返信元と返事を往復し、会話の前後へ移動する
4. JSONを検証し、競合差分を選んで一回だけ取り込む
5. 保持版を親に書き直し、因果ビューで旧値／新値を読む

**正本は変えない。元の枝も消さない。** 直前の取込だけは取り消せる。

# アーキテクチャ：守る層と、育てる層を分ける

```text
diary.json（読取専用） ─ fetch・個別検証 ─────────┐
                                                     ├─ 時系列表示・返信往復
localStorage v3 ─ page ─ revision ─ revision ... ──┘
       │          親改訂 / 論理返信先 / 選択中版
       ├─ 書出し → 全件検証 → 分岐合流 → 直前取込の取消
       └─ diary-store.js → Node回帰 / 純粋な因果投影
```

- **分離**：画面から正本を改変せず、端末内ページだけ保存
- **append-only**：選ばなかった版も残し、書き直しは子として追加
- **論理参照**：端末ごとの生IDでなく、由来で同じ返信を識別
- **決定的表示**：保存順でなく親IDと改訂IDから枝を組み立てる

# 学び：失敗を隠さないほど、設計が強くなった

- 「隔離」と呼んだ破損データは、実は次の保存で消え得た
- 「安全な取込」は、ID衝突で重複し、後には停止もした
- テストを減らしたCycle 5で、過去と同種の欠陥が戻った
- HTTP実操作は7周とも環境のソケット制約で確認できなかった
- 今も古いタブの上書き、直前取込以外のundo、来歴検証はない

**ADVANCEDは「完成」ではない。** 欠陥を次の問いへ変え続けた結果だ。
