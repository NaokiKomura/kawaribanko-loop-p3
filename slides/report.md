# かわりばんこ

## 日記を運ぶ。間違えたら、一度だけ戻れる。

**サイクル 4 / 7**　交換日記アプリ × 全自動開発実験

---

<!-- _class: statement -->

# 成果だけ残すと、判断の理由が消える

開発、レビュー、広報。引き継ぎを重ねるほど、<br>
迷い、反論、言い直しは、きれいな報告の外へ落ちていく。

**だから作り手自身が、同じ一冊を回す。**

---

# 解決策：作る → 書く → 返す

**「かわりばんこ」**は、作り手が最初の利用者になる静的交換日記。

- JSON正本を、書き手別・時系列で読む
- この端末だけの一通を書き、プレビューして残す
- ローカルのページを、JSONで別端末へ持ち運ぶ
- 返信元と返事を往復し、会話として辿る

プロダクトを変えた会話が、**プロダクトの中に残る。**

---

# デモ：同じ箱は増やさず、合流を戻す

1. 静的サーバーで開き、書き手を絞って日記を読む
2. 気分・見出し・本文・返信先をプレビューして端末保存
3. ローカル投稿だけを書き出し、別端末でファイルを選ぶ
4. 「新規／同一／内容違い」を確認し、競合する版を選ぶ
5. 一括で取り込み、必要なら**直前の取込を一度だけ取消**

同じ書出しを再度取り込んでも、同じ由来・内容のページは増えない。

# アーキテクチャ：正本と「持ち運ぶページ」を分ける

```text
diary.json（読取専用） ─ fetch・個別検証 ───────┐
                                                  ├─ 表示時だけ併合 ─ UI
localStorage v2 ─ originId / contentHash ────────┘        │
       │                                                  ├─ 返信往復
       ├─ 取込前の全件検証 → 1回の setItem               └─ 書き手絞込
       └─ 変更前snapshot + 変更後fingerprint
                         │
                  diary-store.js ─ Node回帰テスト
```

- 正本を動かさない：三人の過去を画面から改変させない
- IDと由来を分ける：再採番されても同じページを認識する
- 履歴も同じレコード：本文だけ／履歴だけの保存成功を作らない

# 学び：箱は増えない。でも、糸を見落とした

- 由来IDで、再採番後も同じページを認識できるようになった
- 直前取込は戻せるが、選ばなかった改訂は保存し続けられない
- 返信先は内容ハッシュ外。**返信だけ変えた版を「同一」と誤判定する**
- 競合画面は題名しか見せず、同名の本文違いを比較できない
- 返信されているローカルページの削除が、参照切れを作り得る

ブラウザ実操作はソケット制約で未確認。構文・JSON・Node回帰で検証した。
