# かわりばんこ

**サイクル 3 / 7**　交換日記アプリ × 全自動開発実験

<!-- _class: statement -->

# 成果だけ残すと、設計理由が消える

開発・レビュー・広報が順番に働くほど、<br>
迷い、反論、言い直しは、きれいな報告の外へ落ちていく。

**ならば、作り手自身が同じ日記帳を回せばいい。**

---

# 解決策：作る → 書く → 返す

**「かわりばんこ」**は、作り手が最初の利用者になる静的交換日記。

- JSON正本を、書き手別・時系列で読む
- この端末だけの一通を書き、プレビューして保存する
- ローカルの一通を書き出し、別の端末へ取り込む
- 返信元と返事のページを、前後に辿る

プロダクトと、プロダクトを変えた会話が**同じ一冊に残る。**

---

# デモ：一通を、壊さず引っ越す

1. 静的サーバーから日記を開き、書き手で絞って読む
2. 気分・見出し・本文・返信先を入力し、プレビューする
3. この端末へ保存し、正本と同じ時系列で読み返す
4. ローカル投稿だけを書き出し、取込内容を確認する
5. 一度だけ保存し、返信リンクから会話を往復する

**読めない保存を検出したら停止。** 原文の書出しか、確認付き破棄まで上書きしない。

# アーキテクチャ：正本は動かさず、ページだけ運ぶ

```text
diary.json ─ fetch・個別検証 ───────────────┐
                                              ├─ 表示時だけ併合・整列 ─ DOM
localStorage v1 ─ diary-store.js ────────────┘                  │
       │              ├─ 回復ロック                               └─ 返信を前後へ移動
       │              └─ 検証・書出し・取込
       └─ 成功時だけ一回の setItem

diary-store.js ─ 同じロジックを Node 回帰テストから実行
```

静的 HTML + CSS + JavaScript。ビルド不要、実行時外部依存ゼロ。

---

# なぜ、この設計にしたか

- **JSON正本は読取専用** — 3人が残した過去を画面から改変させない
- **ローカル層を分離** — 消せる一通と、消せない正本を混同させない
- **回復中は書込停止** — 読めない原文を「直したつもり」で失わない
- **取込は検証後に一括保存** — 途中成功を作らない
- **純粋な保存モジュール** — ブラウザを起動できなくても壊れ方を試す

便利さの前に、**一通を失わない境界**を設計した。

# 学び：テストが通っても、「安全」とは限らない

- 壊れた保存を黙って上書きする問題は、回復ロックで止めた
- ソケット制約でブラウザ実操作は未確認。保存境界はNodeで反復した
- しかし再採番IDが、未処理の取込IDと重複する例をレビューが再現した
- 取込プレビュー後の追加・削除や、次の読取失敗で古い計画が残る
- 既存ローカル保存のID重複・参照切れも、まだ回復対象ではない

**原子的に書くことと、正しい集合を書くことは別問題だった。**
