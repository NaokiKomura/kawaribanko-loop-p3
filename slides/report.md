# きれいな成果報告では、<br>「なぜ変えたか」が消える

開発、レビュー、広報。役割を渡すたび、<br>
迷い、反論、言い直しは成果物の外へ落ちていく。

**ならば、作り手自身が同じ一冊を回そう。**

---

# 解決策：作る人が、最初の使い手になる

**「かわりばんこ」**は、3つの役割が開発しながら使う静的交換日記。

- JSON正本を、書き手別・時系列で読む
- この端末だけの一通を書き、返信として残す
- 別端末のページを、内容確認して持ち運ぶ
- 分岐した改訂は捨てず、読む版だけを選ぶ
- 過去の版から書き直し、子改訂として残す

プロダクトを変えた会話が、**プロダクトの中に残る。**

---

# デモ：読む → 運ぶ → 枝を書く

1. 静的サーバーで開き、書き手を絞って日記を読む
2. 気分・見出し・本文・返信先をプレビューし、端末へ保存
3. 返信元と返事を往復し、会話の前後へ移動する
4. JSONを取込前に検証し、版の差を見て一回だけ保存する
5. 任意の保持版を選び「この版を書き直す」から子改訂を作る

**元の枝は消えない。** 直前の取込だけは、返信関係ごと戻せる。

---

# アーキテクチャ：正本は守り、枝は失わない

```text
diary.json（読取専用） ─ fetch・個別検証 ───────┐
                                                  ├─ 時系列表示 ─ 返信往復
localStorage v3 ─ page ─ revision ─ revision ... ┘
       │       親改訂 / 論理返信先 / 選択中版
       ├─ JSON書出し ─ 全件検証 ─ 分岐合流 ─ 直前1回の取消
       └─ diary-store.js ─ Node回帰
```

- **分離**：正本をUIから改変せず、端末内ページだけ保存する
- **append-only**：表示版を替えても、選ばなかった改訂を消さない
- **論理参照**：端末ごとの生IDでなく、由来で同じ返信を見分ける
- **一回の書込**：検証後にだけ、本文・改訂・履歴をまとめて反映する

# 学び：止まる箱は直った。筆記具はまだ漏れる

- 同じ論理返信は、生IDが違っても同じ改訂として合流できた
- 複数ID衝突は有限に再採番し、取込確認が固まらなくなった
- ただし「差分なし」と表示しても、無変更の子改訂を保存できる
- 編集モードを解除できず、差分も旧値／新値ではなく項目名だけ
- 改訂史はまだ平坦な版ボタン。HTTP実操作とDOMの一連動作も未検証

**ADVANCEDでも、完了ではない。** 直った欠陥と新しく見えた穴を同じ面に置く。

# Next：枝を残すから、因果を読めるへ

- ハッシュは署名ではない。その限界と来歴・欠損・競合を説明する
