# かわりばんこ

## 「書ける」ようになった。だから、失う怖さが見えてきた。

**サイクル 2 / 7**　交換日記アプリ × 全自動開発実験

---

<!-- _class: statement -->

# 成果だけでは、次の設計理由が消える

開発・レビュー・広報が順番に動くほど、<br>
迷いと反論は、きれいな報告の外へ落ちていく。

**ならば、作り手自身が同じ日記帳を回せばいい。**

---

# 解決策：作る → 使う → 返す

交換日記アプリ **「かわりばんこ」** は、
3つの役割が一通ずつ本音を返し、次の設計へつなぐ一冊。

- JSON正本を、書き手ごとの色と時系列で読む
- 端末だけの一通を書き、プレビューして残す
- 正本と端末投稿を同じ流れで読み、保存境界は見失わない

**プロダクトの履歴と、プロダクトを作った会話が重なる。**

---

# デモ：読むだけの一冊から、返せる一冊へ

1. 静的サーバーから一冊を開き、正本の日記を読む
2. 気分・見出し・本文・返信先を入力する
3. プレビューで、保存する内容を確かめる
4. この端末へ保存し、正本と同じ時系列で読み返す
5. 紫の「この端末のみ」だけを、確認して削除する

正本のページに削除操作は出ない。**書けても、正本は傷つけない。**

# アーキテクチャ：正本と「この端末」を混ぜない

```text
diary.json ─ fetch ─ 個別検証 ─┐
                                 ├─ 表示時だけ併合・整列 ─ DOM
localStorage v1 ─ 個別検証 ─────┘                │
      ▲                                          └─ 書き手フィルター
      └─ 入力 ─ 検証 ─ プレビュー ─ 保存 / 削除
```

静的 HTML + CSS + JavaScript。ビルド不要、実行時外部依存ゼロ。

---

# なぜ、この設計にしたか

- **JSONは読取専用** — 3ロールが残した過去を画面から改変させない
- **`localStorage` は別スキーマ** — 端末投稿を持ち運ぶ将来に備える
- **個別検証して表示** — 1件の形式不正で一冊すべてを止めない
- **プレビュー後の変更は再確認** — 見た内容と保存内容を一致させる
- **ローカルだけに札と削除** — 保存場所と操作権限を同じ見た目で伝える

便利さより先に、**どの一通を誰が消せるか**を決めた。

# 学び：前進すると、失敗の半径も広がる

- 「この端末のみ」を見た目と削除権限の両方で示せた
- しかし不正データは、次の正常保存で上書きされる恐れがある
- ID重複と `replyTo` の参照切れは、まだ検証していない
- ソケットとChromiumの制約で、ブラウザ実操作を再現できなかった
- 構文・JSON・参照先は確認済みでも、保存境界の回帰テストが足りない

**レビューの痛い指摘は、隠す欠点ではなく次の設計条件。**

# Next：ページを引っ越し、返事を往復する

まず「隔離」を、元データを失わない回復可能な挙動へ。

**バージョン付き書き出し → 全件事前検証 → ID衝突解決 → 原子的取込**

そのうえで `replyTo` を辿り、返事の前後へ移動する。<br>
失敗時は一通も変えず、正本はこれからも読取専用。

> 「持ち運べる」と言う前に、こぼれた一通を救う。
