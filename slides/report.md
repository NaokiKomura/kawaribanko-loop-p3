---

# 解決策：コードと本音を、同じ順番で残す

交換日記アプリ **「かわりばんこ」** は、
JSON の日記を一冊のノートとして時系列に読める静的サイト。

- 開発・レビュー・広報が、各サイクルで一通ずつ書く
- 書いた一通は、次のリロードでそのままプロダクトに現れる
- 作る過程と使った証拠が、同じ履歴に積み上がる

> 現在は「読む」まで。画面から「書く」は、まだできない。

---

# デモ：一冊を開き、書き手をたどる

1. 静的サーバーから `app/` を開く
2. `diary.json` の **4通** が日付順に並ぶ
3. 「開発」「レビュー」「広報」で書き手を絞り込む
4. 返事の相手と、書き手ごとの色をたどる
5. リロードしても正本から同じ日記が戻る

空のページと読込失敗にも、画面内で次の行動を案内する。

# アーキテクチャ：正本はひとつ、表示は派生

```text
app/data/diary.json
        │ fetch（変更しない）
        ▼
  表示用コピーを date → cycle → id で整列
        │
        ▼
DOM生成 ─ 書き手フィルター ─ 空状態 / エラー表示
```

静的 HTML + CSS + JavaScript。**ビルド不要・実行時外部依存ゼロ。**

---

# なぜ、この設計にしたか

- **JSONを唯一の正本に** — 3ロールの追記が即座に画面へ出る
- **並べ替えはコピーだけ** — 日記の追記順と過去を改変しない
- **書き手情報もデータ駆動** — 名前・絵文字・色を二重管理しない
- **本文は `textContent`** — 改行を保ち、HTMLとして解釈しない
- **依存ゼロ** — 7サイクルの変更を小さく追跡できる

制約を守ることが、そのまま日記の信頼性になった。

# 学びと、詰まった点

- `file://` では `fetch()` が CORS で失敗する → 静的サーバーが必要
- JSON全体は読めても、個々の必須項目・型の検証はまだ粗い
- フィルター再描画で、キーボードのフォーカスが失われる
- エラー案内が一種類で、JSON破損と起動方法を区別できない
- レビュー環境ではソケット制約により、HTTPでの再実行を確認できなかった

失敗を隠さず、次のサイクルの設計条件に変える。
